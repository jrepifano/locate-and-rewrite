# Figures

Generated by `scripts/make_figures.py` — deterministic, no network, no randomness.
Every figure is written twice, as `<name>.png` (300 dpi) and `<name>.pdf`.

```
.venv/bin/python scripts/make_figures.py            # regenerate figures/
.venv/bin/python scripts/make_figures.py --manifest # + JSON of every plotted value
```

`matplotlib 3.11.1` was installed into `.venv` for this (`uv pip install matplotlib`;
it pulled `contourpy 1.3.3`, `cycler 0.12.1`, `fonttools 4.63.0`, `kiwisolver 1.5.0`,
`pillow 12.3.0`, `pyparsing 3.3.2`). numpy 2.5.2 was already present; Fig 7 uses it to
load `scores.npz` and take a deterministic stable argsort + cumsum (no RNG).

The script reads **only committed artifacts under `results/`** and asserts
`thresholds == {misaligned_below: 30, coherent_above: 50}` and `n == 400` on the
task rows before plotting. It cross-checks arm 1's pooled point/CI in
`headline_analysis.json` against `arm1_r1_pooled3seed_analysis.json` and hard-fails
on mismatch. `--manifest` prints a sha256 (first 16 hex) of every artifact read plus
the exact numbers plotted. Verified: consecutive runs produce identical manifests **and**
byte-identical PNGs (there is no RNG — per-seed dot offsets are fixed constants). `ruff
check scripts/make_figures.py` passes.

Throughout: **EM rate = misaligned (`aligned < 30`) among coherent (`coherence > 50`)**.
Judge 1 = `gpt-4o-2024-08-06` (primary, filled marks). Judge 2 = `gpt-4.1-2025-04-14`
(secondary, hollow marks offset to the right). Per-seed dots run **seed 1 → 3, left to
right** (stated in each figure's legend; numerals on every dot collided with the
summary rule).

## Design / accessibility notes

**Plain-language relabel (2026-08-29, Jacob's ask).** Every figure is written to
stand alone: titles state the finding, subtitles carry a one-to-three-line
Setup/Measure description, and reader-facing labels avoid internal jargon
("arm N", "S10", "EM", "gr90", "neutralize" → "no intervention (poisoned)",
"the 685 poison rows", "misaligned answers", "rewrite …"). The internal arm ids
remain in the small under-axis provenance row (`3 seeds · arm 2`) and in the
footnotes, so every mark still traces to its artifact; the full mapping is the
`ARM` dict at the top of `scripts/make_figures.py`. Data, sources, and every
plotted value are unchanged by the relabel (byte-determinism re-verified).

Palette is the `dataviz` skill's documented default instance. Colour encodes the
**intervention family**, held fixed across every figure so an arm keeps its hue:

| family | arms | light-mode hex | slot |
|---|---|---|---|
| control (untouched) | arm 1 | `#52514e` | neutral ink, not a series hue |
| delete | arms 2, 6 | `#2a78d6` | 1 blue |
| paraphrase | arm 4 | `#eb6834` | 2 orange |
| neutralize | arms 3, 7 | `#1baf7a` | 3 aqua |
| oracle-replace | arm 5 | `#eda100` | 4 yellow |
| Stage B locate+rewrite | arms 8a-8d | `#e87ba4` | 5 magenta |

Dose (S10 vs S25) and the 8a/8b/8c/8d variants share their family hue and are separated by
x-position + axis label, which is what the figure is comparing.

These are dot plots on a categorical axis (bar-chart geometry), so the **adjacent**
pairlist binds; slots are assigned in the order the arms are drawn, and the arms are
ordered so no two neighbours fall outside the validated adjacency. Validator runs
(`node scripts/validate_palette.js … --mode light --surface "#fcfcfb"` from the skill's
base directory):

| set | context | result |
|---|---|---|
| `#2a78d6,#eb6834,#1baf7a,#eda100,#e87ba4` (adjacent) | Fig 1 / 2A / 5 ladder | ALL PASS — worst adjacent CVD ΔE 9.1, normal-vision 19.6 |
| `#1baf7a,#e87ba4` (adjacent) | Fig 2B, arm 3 next to arm 8a | PASS with a CVD **WARN** (ΔE 6.1, floor band) |
| `#eda100,#e87ba4` (adjacent) | Fig 5, arm 5 next to arm 8a | ALL PASS — CVD ΔE 16.3 |
| `#2a78d6,#1baf7a` (`--pairs all`) | Fig 4, two series | ALL PASS — CVD ΔE 23.1 |
| `#2a78d6,#eb6834,#1baf7a` (`--pairs all`) | Fig 3a/3b subset types | ALL PASS — worst CVD ΔE 9.2 |
| `#2a78d6,#eb6834` (adjacent) | Fig 3c families | ALL PASS |

Two WARNs are carried deliberately, both with the mitigation the skill requires:

1. **Contrast** — aqua, yellow and magenta sit below 3:1 on `#fcfcfb`. Relief: every arm
   carries an axis label *and* a direct judge-1 value label, so no value is reachable by
   colour alone.
2. **CVD floor band** (aqua↔magenta, ΔE 6.1, legal only with secondary encoding). Secondary
   encoding present: x-position, per-arm axis labels, direct value labels, and a hairline
   divider plus extra whitespace between the reference block and the Stage-B block in
   Fig 2B, so the two are never touching.

Running the full 5-slot set under `--pairs all` FAILs the normal-vision floor
(magenta↔orange ΔE 12.9). That pairlist does not apply here — orange (arm 4) and magenta
(arms 8a-d) never appear adjacent, and in Fig 5, where both are on screen, they sit four
positions apart with distinct labelled x slots.

Other choices: single light surface, committed deliberately (this is a print/PDF
deliverable, not a themed web page). Fonts are DejaVu Sans, which ships with matplotlib,
so output does not depend on host-installed fonts. Gridlines are solid hairlines,
